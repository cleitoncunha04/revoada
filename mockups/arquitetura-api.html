Serviços

Cada serviço valida o JWT sozinho (defesa em profundidade) e só acessa o próprio schema.

Fluxo: aluno termina um teste

  1. 1POST /api/assessment/attempts/:id/submit → API HUB valida o JWT e repassa ao Assessment.
  2. 2Assessment confere o tempo, corrige, grava no schema assessment e responde o aluno.
  3. 3Publica attempt.submitted e attempt.graded no Redis Streams.
  4. 4Skills consome attempt.graded e recalcula as aptidões. Gamification consome attempt.submitted e dá as penas (sem ver a nota).
  5. 5Gamification conclui a missão e publica notification.mission-completed.
  6. 6API HUB consome notification.* e envia pelo SSE ao APP HUB, que avisa o <rv-missions>.

Fluxo: professor publica um vídeo

  1. 1POST /api/media/uploads → Media valida o papel "professor" e devolve uma URL pré-assinada (PUT, 15 min).
  2. 2O navegador envia o arquivo direto para o S3. Os 400 MB nunca passam pelo gateway.
  3. 3POST /api/media/uploads/:id/complete → Media confere se o objeto existe no bucket e grava os metadados.
  4. 4Publica material.published. Catalog consome e atualiza os contadores do tópico.
  5. 5O aluno pede GET /api/media/materials/:id/download e recebe uma URL pré-assinada temporária para assistir.
